# Compliance rule packs

Code: `packages/rules`. Seed: `packages/rules/packs/in-seed.json` — **SAMPLE DATA ONLY, UNVERIFIED.** Every rule has
`verified: false` until checked against an official notification and given a `source`.

## Rule format (validated by zod in `src/types.ts`; JSON Schema export planned)
| Field | Meaning |
|---|---|
| `id` | stable key, e.g. `gst.gstr3b.monthly`. Multiple versions share the id with different `effectiveFrom`. |
| `regime`, `form`, `title` | display data — renumbering under ITA 2025 is a data change. |
| `frequency` | `monthly` / `quarterly` / `annual` (FY, April–March) / `event` (generated by triggers, e.g. AGM date). |
| `applicability` | predicate over client facts: `{ all: [...], any: [...] }`, ops `eq neq in nin gt gte lt lte truthy`. |
| `due` | `{ anchor: period_start|period_end|fy_start|fy_end, addMonths, day: 1-31|"last" }`; day clamps to month length. |
| `periodOverrides` | per period-end-month exceptions (e.g. March TDS deposit → 30 April). |
| `holidayShift` | `none` / `next_working_day` / `previous_working_day`. Statutory and act-by dates are both kept. |
| `effectiveFrom/To` | the version in force is chosen by period start date. |
| `penaltyHint`, `serviceTypeKey` | indicative calculator link; links to service catalogue + check template. |

Examples: "7th of next month" = `{anchor: period_end, addMonths: 1, day: 7}`; "31 Jul of following year" =
`{anchor: fy_end, addMonths: 4, day: 31}`; "last day of month following quarter" = `{anchor: period_end, addMonths: 1, day: "last"}`.

## Extensions
`{ id, ruleId, periodKey, newDueDate, scope }` — scope is a predicate (all clients / state / turnover band).
Publishing one runs `diffSchedules(before, after)` → "N due dates changed for M clients"; a partner approves before tasks and
reminders are rescheduled.

## Update channel
Server publishes pack version `x.y.z`; each firm sees the diff against its active version and approves. Firm-local
overrides layer on top and survive pack updates.

## Known simplifications (see KNOWN_GAPS)
AOC-4/MGT-7 are really event-based (days from AGM); seed uses the common default. ITR dates differ by form/category and changed
in 2026 — seed values are placeholders. Event frequency is not yet generated by `schedule()`.

## Tests
`packages/rules/src/engine.test.ts`: golden dates per rule, leap years, day clamping, holiday shift, FY rollover, scoped
extensions, effective-dated versions, duplicate detection.
