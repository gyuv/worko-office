# Worko v1.0.0

This is the first complete build of the roadmap (phases 0–12). **It is not ready for production yet.** Work through
"Before going live" below first.

## What's included
- **Foundation and sync**
  - Each firm's data is kept apart, and every change goes into a tamper-evident audit log.
  - The web, desktop and Android apps work offline and sync with live updates.
  - Notifications respect quiet hours.
- **Clients and documents**
  - GSTIN/PAN validation, rules for who can see which client, and encrypted personal data.
  - A credential vault, with a browser extension that fills in logins on official government portals.
  - A document store with versions and share links.
  - Inward/outward registers.
- **Tasks and compliance**
  - A service catalogue, with tasks created automatically from the compliance rule packs.
  - Checklists and review steps.
  - A compliance matrix, due-date extensions and indicative late fees.
- **Billing and collections**
  - GST invoices, credit/debit notes and receipts with TDS.
  - Ageing reports.
  - Automatic invoice drafts, retainers, payment reminders and payment links.
  - Export to Tally (XML).
- **Time and HR**
  - Timers, timesheets, cost rates, job profit and loss and staff capacity.
  - Attendance, leave and expenses.
- **Communication**
  - Email, WhatsApp and SMS that respect client consent.
  - Message templates, spending caps and broadcasts.
  - A timeline per client and team chat.
  - Calendar feeds (ICS) and booking pages.
- **Practice**
  - Notices and hearings.
  - Audit workpapers and sign-offs; audit tasks need a UDIN before they can close.
  - DSC register, licences and e-signature.
- **Client portal and CRM**
  - A client portal with one-time-code login, where each client sees only what they've been granted. Clients can upload documents, answer requests and pay.
  - A leads pipeline, versioned proposals, and conversion of an accepted proposal into a client.
- **Automation and AI**
  - Automation rules and prebuilt agents, with dry runs.
  - AI is off by default. When a firm turns it on, personal data is redacted and every suggestion needs a person's approval.
- **Reports**
  - A report catalogue and builder, dashboards and drill-down.
  - Exports, scheduled reports and questions in plain language.
- **Platform**
  - A super-admin console, SaaS plans and seat limits, and support access only with the firm's consent.
  - DPDP (data protection) tools.
  - Public API keys and signed webhooks.
  - Security hardening.
- **Release tooling**
  - Backup, restore and a restore drill.
  - Desktop installers (only the Linux one has been built and tested).
  - Android App Bundle configuration.
  - A user manual.
  - The ten-step "Firm's day" end-to-end test, which passes 10/10.

## Before going live
1. **Upgrade dependencies.** `pnpm audit` flags 4 critical and 49 high vulnerabilities. Fixing them needs upgrades of NestJS, Electron, Vite/Vitest and Expo.
2. **Decide about old audit entries.** Some entries written before a hashing fix (D200) fail the integrity check; the options are in KNOWN_GAPS.
3. **Set up signing and build the installers.** Get code-signing certificates for Windows and macOS, and an Android keystore with EAS. Then build the Windows and macOS installers and the Android bundle.
4. **Verify against official sources:**
   - every third-party adapter: Razorpay, WhatsApp, SMS/DLT, Gmail/Outlook, the e-sign provider, Tally and Anthropic
   - all statutory and legal data: compliance rule packs, late fees, GST invoice fields and DPDP time periods
5. **Confirm and test.**
   - Check the "Firm's day" steps in docs/PRD.md §15 against the original requirements.
   - Test the Android app on real phones.
6. **Configure production.**
   - Never deploy the demo logins.
   - Set the production environment variables listed in docs/RELEASE.md (`WEB_PUBLIC_URL`, `TRUST_PROXY` and the secrets).
