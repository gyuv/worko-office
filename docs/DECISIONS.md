# Decisions

| # | Decision | Why |
|---|---|---|
| D1 | pnpm + Turborepo monorepo, TypeScript ESM everywhere (API included) | Shared zod schemas/types across API, web, desktop, mobile; ESM avoids CJS/ESM interop errors with shared packages. |
| D2 | Hand-written ordered SQL migrations (`apps/api/db`, own runner) + parameterised queries via `pg`. **Revised in Phase 1:** Drizzle deferred until module tables (Phase 3) where typed query building pays off; not Prisma. | RLS policies, triggers, procedures and grants are first-class in SQL; Prisma's migration engine fights RLS. Auth/audit queries are few and security-sensitive, so explicit SQL is easier to review. |
| D3 | Tenant isolation via Postgres RLS on `current_setting('app.tenant_id')` set with `SET LOCAL` per transaction; tables use `FORCE ROW LEVEL SECURITY` | Defence in depth: a missing `WHERE tenant_id` in app code cannot leak data. Verified locally (cross-tenant insert rejected). |
| D4 | Sync cursor = global Postgres sequence bumped by trigger on every insert/update | Monotonic, gap-tolerant, no clock dependence; clients pull `cursor > n`. |
| D5 | Field-level LWW by **server receive order** (not client clocks); losing values go to a conflict log. "Strict" tables (invoice, receipt, filed status) use optimistic concurrency and reject stale writes | Immune to device clock skew; money/legal records never silently overwritten (spec §8). |
| D6 | Due dates as structured expressions `{anchor, addMonths, day}` + per-period overrides, not free-text | Machine-checkable by JSON Schema, golden-testable, editable by non-engineers in an admin UI. Free-text like "7th of next month" is rendered from the structure. |
| D7 | Rule versions are effective-dated by period start; a pack version is a full snapshot | Firms can diff two versions and approve; past periods keep their historical rule. |
| D8 | Money as integer paise | No floating-point drift in GST splits and ledgers. |
| D9 | Statutory "due" and holiday-shifted "act-by" both stored | Spec §5.4; shifting is a per-rule policy since not every law shifts. Default `none`. |
| D10 | Regime: FY ≤ 2025-26 labelled "FY/AY" (ITA 1961); from 2026-27 "Tax Year" (ITA 2025) | Spec §6; both coexist; form names remain data. |
| D11 | Web: React + Vite SPA; client portal as a separate Vite entry with white-label theme (no SSR needed — portal is behind login) | Simpler than Next.js; shares renderer with Electron. |
| D12 | Desktop: Electron + better-sqlite3 with SQLCipher; mobile: Expo dev-client + op-sqlite (SQLCipher) | Both run `@worko/sync` unchanged. |
| D13 | AI via one `AiService` with redaction; default model configurable via `AI_MODEL` env | Model-agnostic; no-AI mode keeps everything functional. |
| D14 | UDIN: record + validate format + deep-link to the official ICAI portal only | ICAI warns against look-alike interfaces; we never imitate generation. |
| D15 | GSTIN checksum validated locally (mod-36 algorithm) before any provider lookup | Saves paid lookup credits, instant feedback. |
| D16 | Audit log is append-only (no UPDATE/DELETE policy) and hash-chained (`prev_hash` → `hash`) | Tamper-evidence for finance and credential reveals (spec §11). |
| D17 | Requests run as non-superuser role `worko_app` via `SET LOCAL ROLE` inside each transaction, plus `set_config('app.tenant_id', …, true)` | Superusers and table owners bypass RLS; switching role per transaction guarantees policies apply whatever the pool's login role is. |
| D18 | Passwords: scrypt (N=2^15) via Node crypto instead of argon2 | No native build on Windows desktops/CI; scrypt is memory-hard and OWASP-acceptable. Format is versioned (`scrypt$N$r$p$…`) so argon2id can be added later. |
| D19 | Access JWT 15 min (HS256, `jose`); refresh token `<tenantId>.<random>` stored hashed, rotated on every use; replaying a rotated token revokes the session | Reuse detection (stolen-token defence); tenant prefix lets refresh run inside the right RLS context without a global lookup. |
| D20 | Login identifies the firm by slug ("Firm ID") | Users are unique per tenant, not globally; avoids a cross-tenant email directory. Client-portal custom domains will map domain → tenant. |
| D21 | Remote wipe = session revoked + `wipe_requested_at`; every authenticated call and refresh returns `401 {code: DEVICE_WIPE}`; clients erase local data on that code | Works for devices that are offline at wipe time — they comply on next contact. |
| D22 | Contract-first API: `docs/openapi.yaml` is hand-maintained; a test asserts routes ≡ spec; `@worko/api-client` is generated with openapi-typescript and CI fails if it's stale | Spec can't drift from code; all three apps share typed calls. |
| D23 | No UI component library yet (shadcn deferred); small Tailwind component classes over CSS variables from `@worko/ui-tokens`; hand-rolled hash router | Keeps the shell small (84 KB gz). shadcn/TanStack Table/Router come with the data-heavy modules in Phase 3. |
| D24 | Web stores tokens in localStorage under a strict CSP; desktop uses Electron `safeStorage` (DPAPI/Keychain/libsecret) and keeps tokens memory-only if unavailable; Android uses SecureStore (Keystore) | Per-platform best available secure storage; never plaintext on desktop disk. |
| D25 | Own tiny i18n (`@worko/i18n`) instead of i18next | Same code on web, Electron and React Native; typed keys; English fallback. Hindi/Tamil catalogues plug in via `registerLocale`. |
| D26 | API dev mode compiles with `tsc` and runs `node --watch` (not tsx) | esbuild/tsx doesn't emit decorator metadata, which Nest DI needs (verified: DI failed under tsx). |
| D27 | Mobile defaults to phone-OTP login; web/desktop default to email + password | Spec "less input"; phones already receive the SMS. Users with TOTP enabled must use password + TOTP. |
| D28 | `bump_sync` takes a per-tenant transaction-scoped advisory lock before assigning the cursor | A global sequence alone lets a slow transaction commit a lower cursor after a client has pulled past it (lost update for that client). Serialising per tenant makes cursor order = commit order. Cost: writes in one firm serialise at the trigger; revisit (xid-snapshot watermark) if a firm's write rate demands it. Proven by a test that holds a transaction open. |
| D29 | Sync registry (`apps/api/src/sync/registry.ts`): each syncable table declares shipped columns, zod-validated writable columns, scope SQL, write rules, strict flag, audit flag | One generic push/pull path; adding a module = one registry entry + tests. Clients can only patch whitelisted fields. |
| D30 | Field versions stored per row (`field_versions jsonb`) for field-level LWW; server-originated writes go through the same `writePatch` | Conflicts are detected identically whether the write came from a device or a REST action/worker. |
| D31 | Notification read/ack/snooze edits are not audit-logged (acknowledgements are) | Read receipts would drown the audit log; acknowledgement is the accountability event (escalation). Exception to CLAUDE.md "every mutation" — documented here. |
| D32 | Postgres `job_queue` (SKIP LOCKED) instead of BullMQ for now; global pointer table the app role can only INSERT into; workers act inside `tenantTx` | Jobs commit atomically with the data that creates them; no Redis needed in tests; cross-tenant table holds ids only. BullMQ/Redis can replace the runner behind `JobQueueService`. |
| D33 | Realtime = raw `ws` on the Nest HTTP server, first-message auth, in-process fan-out | Works identically for browser, Electron and React Native; tokens never in URLs. Multi-node needs Redis pub/sub behind `RealtimeService` (gap). |
| D34 | Default quiet hours 21:00–08:00 IST; `critical` bypasses mutes and quiet hours; "send test notification" is critical | Professional default; hearings/security alerts must not be silenced; a test that's deferred at night would look broken. |
| D35 | Web/desktop offline store = IndexedDB; desktop values AES-GCM-encrypted with a 32-byte key kept by OS keychain (safeStorage), destroyed on wipe. Android = expo-sqlite with SQLCipher, key in Keystore | Spec asks SQLCipher on desktop; Electron 33's Node lacks `node:sqlite` and native better-sqlite3 needs per-platform rebuilds. WebCrypto-encrypted IDB gives encryption at rest with zero native code; same store code on web. |
| D36 | Client engine keeps the last server copy of each row and reverts rejected local edits immediately | A device must never keep showing a value the server refused. |
| D37 | Reminder scheduler `prime()` on startup: already-due items go silently to the inbox; only items that come due/arrive while running pop up | Otherwise opening the app sprays toasts for the whole day. |
| D38 | Android pre-schedules the next 7 days of reminders (≤60) as exact OS alarms, rescheduled on every sync | Fires when the app is killed/offline or push is delayed (spec §7 fallback). |
| D39 | ESLint flat config (typescript-eslint recommended + react-hooks), `--max-warnings=0` in CI; type-only-import rule disabled in `apps/api/src` | Nest DI needs runtime class imports for constructor parameters. |
| D40 | Client visibility has one definition (`clientCtx` + `can()` in `@worko/domain`) and one SQL twin (`clientScopeSql`), proven equivalent by a 3000-case property test against Postgres | Lists, sync, search, duplicates, documents, vault and registers all filter the same way; drift is caught by CI. |
| D41 | Visibility columns (branch/partner/manager/team/staff/groups/sensitive/allowed users) are REST-only; `PUT /clients/{id}/access` computes who could see the client before vs after and writes `sync_revocation` rows only for users who lost access; children are touched so users who gained access receive them | Devices purge rows they should no longer hold without anyone learning about clients they could never see. |
| D42 | `scopeKey` (hash of grants, teams, branch, hidden fields) in every pull; a change makes the device wipe synced rows and re-pull from zero (outbox kept) | Role/team/branch changes can't be expressed as row revocations cheaply; a full re-pull is simple and always correct. |
| D43 | Sensitive clients: the person marking a client sensitive, its partner and manager are always added to the allow-list; a scope change that would lock the editor out is refused | Prevents orphaned clients nobody can see. |
| D44 | Envelope encryption: per-tenant 256-bit DEK, wrapped by a `KmsProvider` (local key in dev; AWS KMS ap-south-1 slot in prod), cached unwrapped 10 min; AES-256-GCM with AAD `tenant:entity:id:field` | Ciphertext can't be moved between rows/columns/tenants; key rotation = re-wrap DEKs. |
| D45 | Credential and PII reveals require a 5-minute step-up on the same session (authenticator code if 2FA is on, else password); every reveal is audited (purpose, portal, host) without the value | Stolen session alone can't read secrets; accountability for every reveal. |
| D46 | Browser extension pairs with a one-time 8-digit code (5 min, 5 guesses) into an `extension` session that the guard limits to vault/step-up/me endpoints; autofill only when the page URL's exact https host is on the portal allow-list (`@worko/domain/portals.ts`), checked by extension and server | Least privilege for a component that lives in the browser; no autofill on look-alike domains. |
| D47 | Documents: bytes never sync; metadata does. Downloads via 2-minute HMAC-signed URLs served as attachments with `nosniff` + `CSP: sandbox`; HTML/SVG/scripts/executables refused at upload | Safe previews/downloads from our origin; mobile/desktop keep working offline on metadata. |
| D48 | Register numbers (`IN|OUT/FY/0001`) assigned server-side at insert (also for offline-created entries, on sync) from a per-FY counter row | Offline devices can't collide on numbers; clients see "assigned on sync". |
| D49 | Import is two-step (preview → commit) with header aliasing (Tally/Excel/other tools), PAN-based entity inference, in-file and in-DB duplicate checks; commit re-validates every row; export neutralises formula-like cells | Safe bulk onboarding; no CSV injection. |
| D50 | Duplicate detection names only visible matches and counts the rest | Can't be used to enumerate hidden/sensitive clients. |
| D51 | A register entry's date (`received_on`/`sent_on`) is immutable after insert; number + FY derive from it. Offline entries are numbered in server-arrival order, not date order | Numbers never disagree with their FY; a wrong date is fixed by cancelling and re-entering. |
| D52 | Changing partner, manager, `sensitive` or the allow-list needs `clients:approve`; a sensitive allow-list always keeps the previous partner/manager. Children (documents, registers, contacts) need `clients:view` **and** their own module's view — same rule in REST, sync scope and revocations. Client delete cascades soft-deletes to documents and register entries | Phase 3 review: no access hijack by plain editors, no leaks of child rows. |
| D53 | Signed download URLs are bound to the minting session (dead after logout/revocation/deactivation); share links revoke themselves after 10 wrong passwords | Bearer URLs can't outlive the session; distributed guessing is bounded. |
| D54 | Rule packs are stored **per tenant** (`rule_pack`: draft → approved → superseded, one approved at a time). The shipped seed pack is installed as approved on first use; uploads are validated with `rulePackSchema` and need firm-wide `compliance:approve` to go live. Packs keep their own `notes` (seed stays "SAMPLE DATA — UNVERIFIED") | Firms adopt rule updates on their own schedule, with a diff ("N due dates / M clients") before approving; no cross-tenant blast radius. |
| D55 | Task visibility = `clients:view` on the client **and** `tasks:<action>` on `taskCtx` (client context + the task's leader/manager/assignee/reviewer as owners). Firm tasks (no client) are firm-wide only (`ResourceCtx.firmWide` blocks branch scope) or visible to their people. SQL twin `taskScopeSql`, proven equal by a 3000-case property test. People named on a task must be able to see it; changing people needs `tasks:assign`; users who lose a task by reassignment get a sync revocation | Same pattern as D40/D52; assignees work their own tasks without seeing the client's other work. |
| D56 | Auto-creation: due items (rule pack + approved extensions) whose period **ends** in the given month × active `client_service` subscriptions → one task per client × service × period (`task_auto_unique` + NOT EXISTS over live *and deleted* rows, so a deleted task is never recreated). Rules link to services by `service_type.rule_id` or else `serviceTypeKey = key`. Assignment: subscription override → service default → client staff → client manager → partner, skipping anyone who can't see the client. `act_by = statutory_due − sla_days` (tenant `settings.tasks.defaultSlaDays` fallback), never after the due | Idempotent preview/commit; M5 "GSTR-3B for every client each month, assigned". |
| D57 | Monthly auto-creation is a per-tenant `tasks.auto_month` job in the Postgres queue that commits the month of its run time (IST) and reschedules itself to the 1st of next month 02:00 IST; handlers receive the queue clock (`runOnce(batch, now)`) so tests inject dates | No cron dependency; idempotent re-runs; no wall clock in tests. |
| D58 | Task business rules live in `@worko/domain` (`taskChangeError`, `closeError`) and run on every write path (REST, device push via the registry's new `validate` hook, bulk). `done` needs all required checks; `review` needs a reviewer; `pending_client` needs an issue; closing is a separate action: billed/free only when done, deleted = soft delete; closed tasks are frozen. Devices cannot delete tasks | "Every task ends billed/free/deleted"; same answer online and offline. |
| D59 | Bulk task edits store a server-side snapshot (`task_bulk_undo`, 10 minutes, single use, only the author) and return an undo token; rows failing rules are reported, not applied | Undo survives page reloads and works across devices; no partial silent failures. |
| D60 | Extension approval (firm-wide `compliance:approve`) moves only **open** tasks of that rule × period in scope (statutory due set, act-by shifted by the same delta and capped at the due) via `serverPatch`; done/closed tasks keep their history; future auto-created tasks pick the extension up | "Publish an extension and see impact before approving" without rewriting completed work. |
| D61 | Late fees are indicative only: rates are data (`packages/rules/packs/in-latefees-seed.json`, `verified: false`), arithmetic in `computeLateFee` (per-day with caps/nil rate/cap-at-tax, flat, interest per month-or-part or per day), all money in paise | Never hard-code statutory amounts; the UI must show the disclaimer. |
| D62 | To-dos are personal (`todo` syncs only to `owner_id`; no module permission needed); to-do templates are firm-wide and "apply" creates the caller's to-dos | Lightweight personal lists separate from billable tasks. |
| D63 | Edit-only task users may tick checks (`done`; who/when is server-stamped) but changing the check set (add/remove/relabel/required) needs `tasks:assign`, like changing people. Moving `review → done` needs the task's reviewer or `tasks:approve` — the assignee can't self-approve. One function (`actorChangeError`) enforces this for REST, device push, bulk and undo | Maker-checker on filings; checklists can't be quietly weakened by the person doing the work. |
| D64 | `POST /tasks/auto/commit` needs `tasks:assign` (on each client) besides `tasks:create`, since it assigns people; preview needs only `tasks:create` | Creating assigned work for others is an assignment. |
| D65 | Bulk undo restores a row only if it still holds exactly the values the bulk wrote and the caller may still make that change under current rules; otherwise it is skipped as `stale`/`forbidden`/`invalid` (DB CHECK failures included). Deleting a client closes its tasks as `deleted` and soft-deletes subscriptions (cascade, not a scope filter, so tombstones still reach devices). One live `tasks.auto_month` job per tenant is enforced by a unique partial index (0008) | Undo never clobbers newer work; every task ends with an outcome; concurrent boots don't double-schedule. |
| D66 | Billing numbers come from a per **entity × series × FY** counter row (`billing_counter`) taken in the issuing transaction: `<PREFIX><SERIES>/<yyYY>/<NNNN>` (series '' invoice, CN, DN, R receipt), prefix ≤ 4 chars so a GST invoice number stays ≤ 16 chars. Drafts have no number. Prefix, state and GSTIN of an entity lock once it has issued anything | Row lock serialises concurrent issues and a rolled-back issue leaves no gap (proven by a concurrent-issue test); numbers never disagree with their entity/FY. |
| D67 | Rounding: each line rounded to the paisa (qty × rate, then each tax component; CGST = SGST = round(taxable × rate/200)); invoice total rounded to the nearest rupee (half up) with an explicit round-off line. Credit/debit notes keep paise (no rupee rounding). Reimbursements (pure-agent expenses) are separate lines with no GST, outside the taxable value. Supplier without GSTIN → no tax ("Bill of Supply") | Equal halves on the face of the invoice; totals reproducible from the lines; one function (`computeInvoice` in `@worko/domain`). |
| D68 | Prices are data: `billing_rate` (service × optional client or group override, effective dates); precedence client > group > firm default, latest `effective_from` wins. SAC + GST % live on `service_type` (NULL → `billing_settings` default 18% / seed SAC, both marked VERIFY) | Never hard-code fees or statutory rates; history preserved by end-dating rows. |
| D69 | (credit cap superseded by D77) Issued documents are immutable — enforced by DB triggers on `invoice` content columns and `invoice_line`, not only in code. Corrections: credit note (≤ current balance) or debit note (a receivable of its own), both issued immediately in their own series. Drafts can be deleted. Cancel = only an issued invoice with nothing settled (no receipts, TDS or notes): status `cancelled`, number stays used; anything settled needs a credit note | GST-safe audit trail; gap-free series; no silent edits. |
| D70 | Follow-ups: per-firm ladder (data, `billing_settings.ladder`) of steps `daysAfterDue → channels (+escalate)`. A daily `billing.followups` job (10:00 IST) sends only the **latest** step reached, once per invoice × step × channel (unique index), logs every message (`billing_message`, recipient masked), escalates in-app to the client's partner (else manager). Stops when paid/cancelled/paused or while `promise_to_pay ≥ asOf` (resumes after it passes). Messages carry number, amount and a link (payment link or 30-day signed invoice link) — never the document | Idempotent, quiet-hours-friendly time of day, no PII beyond invoice content. |
| D71 | Receipts: cash + TDS (section required) allocated FIFO over the client's open receivables (oldest due first) — TDS applied before cash on each — or manually; the remainder is an advance (`unallocated_paise`) applied later. `balance = total − allocations − TDS − credit notes`, recomputed in the same transaction as any allocation/note (status issued → partially_paid → paid); `CHECK balance ≥ 0` | Matches how firms reconcile 26AS/TDS; ageing and client balances always reconcile (tested). |
| D72 | Sync: `invoice` and `receipt` **headers** sync read-only (strict) to devices, client-scoped (`clients:view` AND `billing:view` / `receipts:view`), hidden from roles that hide `invoice.*`; lines, allocations, rates, messages stay server-side. Devices never write billing rows; mobile records receipts via REST (online-only). bigint paise ship as decimal strings in sync | Money records can't fork offline; the phone still shows outstanding/invoice lists offline. |
| D73 | Billing permissions: drafts/issue/send/payment link = `billing:create/edit`; cancel and credit/debit notes = `billing:approve` (maker-checker: accountants issue, partners/managers correct); PDFs = `print`; registers = `export` (audited, client-scoped). Firm config (entities, settings, rates, Tally ledgers, manual follow-up run) = firm-wide `settings:edit`; Tally export = firm-wide `billing:export` | Same pattern as the Phase 4 catalogue (D54/D64). |
| D74 | Task ↔ invoice links live in `invoice_task` with a `live` flag and a unique index on `task_id WHERE live`: a task is on at most one non-cancelled invoice. Linking (also for drafts, incl. auto-billing) sets `task.outcome = billed` via `serverPatch`; deleting the draft or cancelling the invoice un-bills (outcome NULL). Auto-billing drafts one invoice per client from done-unbilled tasks completed in the range, priced from rates; unpriced tasks are reported, not billed; services on a retainer (`client_service.billing_frequency`) are excluded and linked to the retainer draft of their period (one per subscription × period, monthly `billing.retainers` job on the 1st for the month just ended) | "Every task ends billed/free/deleted" with DB-enforced idempotency. |
| D75 | Payments: `PaymentProvider` adapter (mock default, Razorpay skeleton). Links are created for the server-computed balance. Webhook `POST /billing/webhooks/{provider}/{tenantId}` is public: HMAC-SHA256 over the **raw** body first, then one `payment_event` per provider event id (replays no-op) and one receipt per provider payment id; amount comes from the signed event; receipt is allocated to the link's invoice (rest = advance), audited, realtime | Never trust client-side amounts; safe retries from the provider. |
| D76 | Tally: pure XML builder (`@worko/domain/tally.ts`) shared with the future desktop connector; ledger map (`tally_ledger_map`, entity-specific rows override firm-wide; `sales:<SERVICE>`/`party:<client>` overrides; party defaults to the client name). Dry-run returns XML + errors (unmapped ledger, unbalanced); export refuses while errors remain and records `tally_export_log`, so re-export skips exported vouchers unless `force`. Cancelled invoices are not exported | Idempotent pushes to Tally; schema assumptions isolated in one module (VERIFY). |
| D77 | Credit/debit note lines must use a GST rate the invoice charged (a single-rate invoice defaults to it). Cumulative credit notes are capped per head (taxable value, CGST, SGST, IGST and reimbursements) at the invoice's figures. Notes may carry untaxed reimbursement lines. A credit note on a paid (or over-settled) invoice is allowed: the part not needed to clear the balance stays on the credit note's own `balance_paise` as **client credit** (latest notes first), shown as `creditPaise` in outstanding/ageing and netted in `netPaise`; applying it to other invoices or refunding it is manual for now | No credit for tax never charged; nothing silently lost; refunds stay a deliberate human action. Supersedes the "credit ≤ balance" rule of D69. |
| D78 | Issue and note dates must be ≤ today (IST, from the injectable `Clock`) and ≥ the last issued date in the same entity × series × FY; checked after the counter row is locked, so a refused issue rolls back without a gap. The entity must be active. The demo seed issues oldest first | Numbers follow date order (GST expects chronological serials); tests pin the clock. |
| D79 | Follow-ups never do external I/O inside a tenant-wide transaction: plan (read) → claim each invoice × step × channel in its own committed transaction (`pending`) → send → record status + audit in another. A `failed` slot is re-claimed on later runs up to 3 attempts; `sent` slots never are. "Send invoice" follows the same read → send → record split | A slow/failing provider can't hold locks or roll back other clients' sends; a crash after a send can't resend the earlier ones. |
| D80 | Public invoice links (`/billing/public/{token}`) are stateless 30-day HMAC tokens; they stop serving when the invoice is cancelled (404) or deleted, but cannot otherwise be revoked before expiry | Accepting a short window; rotate `JWT_SIGNING_KEY` to kill all links. |
| D81 | Payment-link webhook hardening: secrets read with `||` (empty = unset); production refuses to boot with the mock provider or a missing/default Razorpay webhook secret; `/webhooks/mock` is served only when `PAYMENT_PROVIDER=mock` outside production; the tenant in the URL must exist and the signature must verify before any row is written. Superseding a link cancels it at the provider (`cancelLink`). Money arriving on a non-live link is still recorded, but as an unallocated advance with `needs_review` and an in-app alert to the client's partner | Unforgeable webhooks; received money is never dropped nor auto-applied twice. |
| D82 | A receipt without `entityId` takes the entity of the client's open receivables; if they span more than one entity the request is refused (`entity_required`); with none open, the firm default | Receipt series and allocations stay within one entity. |
| D83 | Firm config reads are scope-filtered where they name clients: client-specific rates and `party:<client>` ledger maps are returned only for clients the caller may view for billing; firm/group rates are a price list and stay visible. Receipt-derived figures (allocations on invoice detail, advances in outstanding/ageing) need `receipts:view` on the client; outstanding returns `advancePaise: null` otherwise | No leakage of invisible clients or of receipt data to billing-only roles. |
| D84 | Time entries are personal records scoped by the **person** (`time:view` over the user — self, their manager by `app_user.manager_id`, or team/branch/all scope — `canPerson` + SQL twin `personScopeSql`) **and**, for anyone but the owner, `clients:view` on the entry's client (D52 adapted: time:view is evaluated on the person, clients:view on the client; invisible → 404). A task's client is copied onto the entry. Owners move draft/rejected → submitted (weekly `POST /time/timesheets/submit`) and may withdraw; approved entries are immutable (DB trigger); corrections are an approved negative reversal (`source = reversal`, once per entry by unique index) plus a new entry. One running timer per user (unique partial index); stop derives minutes from server timestamps, capped at `hr_settings.timer.capMinutes` (default 720) and flagged `capped`. Live activity lists every running timer but names the task/client only when the viewer may see it ("Busy" otherwise); a stop never pushes the IST day over 24 h — minutes are clamped to what is left (flagged `capped`), and a full day stops the timer without an entry; start/stop publish a realtime `changed` | M10 timers/approval with the existing visibility model; offline edits can't rewrite approved time. |
| D85 | Permission mapping: M10 uses module `time`; attendance, leave and expenses use `hr` (no new modules). Own-record actions need any `edit` or `create` grant on the module (`canOwn`) — articles (`time`/`hr` own view+edit) log time, check in, apply for leave and claim expenses without a role change. Firm config (HR settings, holidays, office fences, leave types, expense categories, capacity) = firm-wide `hr:edit`; payouts, accrual, comp-off runs and ledger adjustments = firm-wide `hr:approve`; re-billing expenses = `billing:view/edit` on the client | Reuses the permission matrix; no migration of tenants' stored roles. |
| D86 | Approver of a person's time, attendance exceptions, regularisations, leave and expense claims/advances = their manager (reporting line) **or** `<module>:approve` scope over the person; nobody approves, pays or adjusts their own record (403 `self_approval`; bulk time decisions report it per entry) | Maker-checker on personal claims. |
| D87 | Cost rates (`cost_rate`, hourly paise with effective dates, previous rate end-dated) are sensitive: readable only with firm-wide `settings:view` or `hr:approve` and not hidden by a role's `cost.*` hidden field (`canSeeCost`); writable with firm-wide `settings:edit`.
